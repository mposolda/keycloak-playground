## OID4VCI presentation with key-binding support

I would like to add the support for sd-jwt key-binding to the functionality provided by the button "Create presentation from last Verifiable Credential" .

In case that last obtained verifiable credential is not bound to the proof key (which means that claim `cnf` does not exists in the obtained credential), the behavior of
 "Create presentation from last Verifiable Credential" should be the same as before. However in case that last credential had key-binding (the claim `cnf` exists),
 the behavior should be that newly created verifiable presentation should be bound to that new key and should contain additional key binding element.

Additional point: To achieve the requirement, I think that it might be needed that proof key is also saved in the fapi-playground in the `OID4VCIContext`. As for
generating key binding in the presentation, the application would need the proof private key. So considering that
it would be good to provide also button `Create proof key`, which would be similar to the "Create attestation key". However the "proof key" does not need to be persisted within `PersistenceProvider`
as proof key does not need to survive application restart. When the `Credential request` is going to be sent and the proof is requested (either `jwt` or `attestation`) and
proof key was not generated by the `Create proof key`, the fapi-playground should display error message in the `InfoBean` similar to "Proof key required" as a title and text like "You need to create proof key before
sending credential request with the proof".

Some sources are:
- Sd-jwt specification https://datatracker.ietf.org/doc/draft-ietf-oauth-selective-disclosure-jwt/22/ (especially section 4.3)
- Unit tests from the Keycloak codebase. Especially tests from the "core" module from the package "org.keycloak.sdjwt.sdjwtvp". Those probably have some examples for how
to create Sd-JWT with the key-binding element
